# SCI 投稿流程参考

本文把用户提供的流程图片整理成可执行的参考框架。图片中的 Day 数是一次投稿经历的示例，不是所有期刊的承诺；目标期刊官网和投稿系统的最新要求优先。

## 阶段总览

| 阶段 | 主要产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 选刊与准备 | 期刊比较表、目标期刊、文件计划 | 范围和文章类型匹配，关键要求可满足 |
| 2. 投稿前核查 | 主文稿、图表、补充材料、声明和 Cover Letter | 文件、作者和声明信息完整 |
| 3. 在线投稿 | 系统字段、上传文件、预览 PDF、确认邮件 | 用户核对并明确确认最终提交 |
| 4. 初审 | 状态记录、必要的格式补充 | 进入同行评审或收到编辑决定 |
| 5. 同行评审 | 审稿意见、状态日志 | 获得决定或编辑要求补充信息 |
| 6. 决定与返修 | 决定分类、回复审稿人、修订稿 | 返修提交、转投或结束该投稿 |

## 阶段 1：投稿前准备

### 期刊筛选

先用论文题目、摘要和关键词做候选检索，再逐本查看官网的范围、近期文章、文章类型和格式。可以用 LetPub、Journal Finder 或 Web of Science 帮助发现候选，但每个关键事实都要回到官网核实。

建议记录：

- 期刊名称、官网链接、查询日期和编辑部联系方式。
- 研究主题与期刊范围的匹配理由，至少列出 2–3 篇近期相近文章。
- 文章类型、字数、摘要和关键词限制、图表要求、参考文献格式。
- 当前索引与指标的来源；不要把第三方分区或旧指标写成确定事实。
- 投稿到首次决定和完整审稿的公开周期，标注“官方公布、作者经验或未知”。
- 接收后的 APC、混合或开放获取选项、版面费和减免政策。
- 数据、伦理、知情同意、注册、预注册、代码或数据共享要求。
- 是否存在预警、异常收费、范围不匹配或无法验证的风险信号。

可以邀请熟悉该领域的导师或同事复核候选期刊。选择理由应同时考虑研究适配度、可信度、成本、时间和作者的实际目标，不能只按影响因子排序。

### 语言、图表与参考文献

把润色拆成自查、工具检查和人工复核：

1. 统一术语、时态、单位、缩写、数字和统计表达。
2. 检查 Abstract、Introduction、Methods、Results、Discussion 的时态和逻辑边界。
3. 逐一核对图表标题、图例、坐标、单位、分辨率、编号和正文引用。
4. 按期刊要求准备 TIFF、PDF、JPG 或源文件；截图中的 300–600 dpi 只能作为常见范围，最终以期刊指南为准。
5. 用 EndNote、Zotero 或期刊模板核对作者、期刊缩写、卷页、年份和 DOI；回到原文确认每条引用。
6. 检查是否需要 Highlights、Graphical Abstract、关键词、数据和代码链接。

语言工具只能指出表达问题，不能替换实验结果、统计方法或科学判断。对任何会改变含义的改写保留版本记录并由作者确认。

## 阶段 2：提交材料清单

| 材料 | 常见形式 | 检查重点 |
| --- | --- | --- |
| Main Document / Manuscript | Word、LaTeX 或 PDF | 包含期刊要求的正文结构，按模板排版 |
| Figures | 单独文件或嵌入正文 | 顺序、清晰度、颜色、图注和文件格式 |
| Tables | 正文内或单独文件 | 表题、脚注、单位、统计标记和编号 |
| Supplementary Information | PDF、表格、数据或方法文件 | 文件名、引用位置、可读性和隐私 |
| Cover Letter | 单独上传或在线填写 | 研究概述、创新点、期刊适配、原创性和声明 |
| Highlights | 通常 3–5 条 | 每条字数和数量按期刊规定，准确概括主要发现 |
| Graphical Abstract | 图像与简短文字 | 尺寸、格式、可读性和是否强制 |
| Conflict of Interest | 表单或声明 | 经济、职业、个人关系如实披露 |
| Reviewer Suggestions | 姓名、单位、邮箱、研究方向 | 真实专家、无直接利益冲突，不捏造联系方式 |
| Ethics / Consent / Data | 表单、编号、声明或链接 | 只使用真实审批、同意和可访问信息 |

上传前生成一个版本清单，例如 `manuscript_v03.docx`、`figures_v03.zip`、`cover_letter_v03.docx`，记录创建日期和对应的最终 PDF。系统生成的预览应逐页检查字体、公式、图表、特殊字符和补充材料链接。

## 阶段 3：在线投稿字段

按以下顺序逐项核对：

1. 用 ORCID 或期刊账号登录，检查姓名、单位和邮箱是否自动填充正确。
2. 选择正确的文章类型，例如 Original Article、Research Article 或 Review Article。
3. 填写与主文稿完全一致的题目、Running Title、摘要和关键词。
4. 按作者顺序添加姓名、单位、邮箱和 ORCID，明确 Corresponding Author。
5. 上传主文稿、图、表、补充材料、Highlights、Graphical Abstract 和 Cover Letter。
6. 填写基金、伦理、知情同意、数据可用性、作者贡献和利益冲突问卷。
7. 提交真实的推荐或回避审稿人，并核查共同作者、导师、同单位和近期合作者等冲突。
8. 查看系统生成的 PDF、文件顺序和元数据；发现问题先返回修改。
9. 用户明确确认后再点击 Submit；保存 Manuscript ID、确认邮件、时间戳和最终文件。

## 阶段 4–5：状态与审稿

| 状态 | 常见含义 | 建议动作 |
| --- | --- | --- |
| Submitted | 系统收到投稿，等待初检 | 保存确认信息，按官网周期等待 |
| With Editor | 编辑初步判断范围、格式或寻找审稿人 | 检查邮箱，避免频繁询问 |
| Under Review | 至少有审稿流程在进行 | 记录起止日期，准备可能的补充材料 |
| Required Reviews Complete | 预计的审稿意见已返回 | 等待编辑综合决定 |
| Decision in Process | 编辑正在形成决定 | 等待正式来信，不根据状态猜测结果 |
| Revision Requested | 编辑允许或要求修改 | 读取截止日期和所有附件，建立回复表 |

状态名称因期刊系统而异。参考公开的平均周期时记录来源和日期，并与该稿件的真实时间比较。超过期刊正常周期且没有更新时，可以发一次简短的 status inquiry；有具体截止日期或时间约束时在邮件中说明事实即可。

## 阶段 6：决定与返修

- **Accept**：核对校样、版权、开放获取和最终文件要求。
- **Minor Revision**：通常先处理文字、少量分析或讨论补充，仍需逐条回复。
- **Major Revision**：先拆分实验、统计、逻辑、图表、引用和语言任务，估算每项时间；必要时与编辑确认范围。
- **Reject**：保存意见，判断是范围不匹配、证据不足、方法问题还是表达问题，再决定转投或重做。
- **Reject and Resubmit**：把它视为需要大幅修改的新一轮投稿，按编辑信要求处理版本、回复和截止日期。

回复表至少包含：

| 编号 | 审稿意见原文 | 回复 | 采取的修改或分析 | 位置/页码 | 证据或附件 |
| --- | --- | --- | --- | --- | --- |
| R1.1 | 保留原文或准确摘录 | 礼貌、直接、可核查 | 说明改了什么或为何未改 | 页、行、图表号 | 新结果、引用或补充文件 |

对未采纳的建议，解释范围、方法或数据限制，并在讨论中承认局限；避免使用“已完成”描述尚未完成的实验。提交前核对回复中的页码、图号、统计数值、主文稿和补充材料是否一致。

## 时间线如何使用

截图把投稿前准备、正式投稿、初审、同行评审、决定和大修分别放在 Day 1–120 的示例中。可以把它转成个人计划，但必须以实际截止日期和期刊周期重新计算：

- 投稿前：按任务量安排选刊、润色、图表、引用和声明；先处理会导致退回的格式问题。
- 提交后：用系统状态和确认邮件记录实际时间，不以固定天数推断决定。
- 审稿中：按期刊当前周期设置提醒，准备可复用的资料，不要每天刷新系统。
- 收到返修：先读完整编辑信和所有审稿意见，设定内部截止日期，留出最终核验时间。

任何计划都应写明来源、假设、负责人和下一次复核日期。若图中的经验与期刊最新指南冲突，采用后者并在计划中留下记录。
